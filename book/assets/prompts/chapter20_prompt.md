#### 4.3 AI Should/Should Not Do

**要求**:
- 列出 3–5 条允许和禁止 AI 做的事情
- 明确边界，避免 AI 超出范围

**模板**:
```
在让 AI 帮助完成本章任务时，我们需要明确 AI 的职责边界。

**✅ AI 允许做的事情**：

1. **生成明确界定的代码**
   - 可以：实现特定优化算法
   - 可以：生成测试用例
   - 不能：修改核心框架

2. **辅助代码审查和优化**
   - 可以：分析代码质量和性能
   - 可以：提出优化建议
   - 不能：改变算法的基本正确性

3. **生成文档和注释**
   - 可以：编写 JavaDoc 和行内注释
   - 可以：生成设计文档
   - 不能：替换现有设计文档

4. **生成测试和验证代码**
   - 可以：编写单元测试
   - 可以：生成基准测试
   - 不能：删除现有测试

5. **提供技术建议**
   - 可以：推荐最佳实践
   - 可以：提供参考资料
   - 不能：改变项目技术栈

**❌ AI 禁止做的事情**：

1. **修改核心框架和接口**
   - 不允许：改变 `IFlowOptimizer` 接口
   - 不允许：修改测试框架
   - 原因：框架是整个编译器的基础

2. **删除或破坏现有代码**
   - 不允许：删除现有优化 Pass
   - 不允许：破坏现有测试
   - 原因：现有代码是经过验证的

3. **引入新的外部依赖**
   - 不允许：添加新的框架或库
   - 不允许：使用项目技术栈之外的依赖
   - 原因：保持项目技术栈一致性

4. **忽略代码规范**
   - 不允许：违反 AGENTS.md 规范
   - 不允许：使用不推荐的编程模式
   - 原因：代码规范是项目质量的保证

5. **生成无法理解的代码**
   - 不允许：生成没有注释的复杂代码
   - 不允许：使用过于晦涩的技巧
   - 原因：代码必须可维护和理解
```

## 回滚方案

如果 AI 修改后出现问题，使用以下步骤快速恢复：

### 方案1：Git Stash（推荐）
```bash
# 查看当前修改
git status

# 保存 AI 修改到 stash（带备注）
git stash push -m "AI changes for {章节名称}"

# 如果出现问题，恢复到修改前状态
git stash pop

# 或者完全丢弃 AI 修改
git stash drop
```

### 方案2：Git Checkout（硬恢复）
```bash
# 查看修改历史
git log --oneline -5

# 恢复到修改前的提交
git checkout {commit_hash}

# 或者恢复特定文件
git checkout HEAD~1 -- {文件路径}
```

### 方案3：Git Reset（危险，谨慎使用）
```bash
# 软重置（保留 AI 修改在 staging）
git reset --soft HEAD~1

# 硬重置（完全丢弃 AI 修改）
git reset --hard HEAD~1

# 混合重置（保留 AI 修改在未跟踪）
git reset --mixed HEAD~1
```

### 方案4：创建新分支实验
```bash
# 从干净状态创建新分支
git checkout -b ai-experiment-{章节名称}

# 让 AI 在新分支工作
# 完成后合并回主分支
git checkout main
git merge ai-experiment-{章节名称}
```

**问题1：AI 生成的代码无法编译**
- 现象：编译错误
- 排查：
  1. 检查 AI 是否使用了不存在的类或方法
  2. 验证依赖关系是否正确
  3. 确认包名和类名是否正确
- 解决：修正 Prompt 或调整 AI 生成的代码

**问题2：AI 生成的测试失败**
- 现象：测试用例失败
- 排查：
  1. 检查测试逻辑是否正确
  2. 验证测试数据是否合理
  3. 确认断言是否正确
- 解决：修正测试或调整 AI Prompt

**问题3：性能未达到预期**
- 现象：优化后性能没有提升
- 排查：
  1. 检查优化是否真正执行
  2. 验证测试用例是否适合该优化
  3. 分析是否有性能开销
- 解决：调整优化策略或改进实现
