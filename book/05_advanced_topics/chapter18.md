本章聚焦于**全局优化技术**，它是编译器流水线中的高级优化阶段。全局优化跨越基本块边界，在整个函数甚至跨函数范围内进行优化。你将掌握四种核心技术：**尾递归优化（TRO）**、**常量折叠与传播**、**死代码消除（DCE）**、以及**循环分析框架**。这些优化能显著提升程序性能，是生产级编译器不可或缺的组成部分。

## 动机与真实场景

### 真实场景

想象你是一名性能工程师，正在优化一个关键算法库：

**场景1：递归深度问题**
一个核心的递归算法（如计算斐波那契数列）在处理大规模数据时频繁崩溃，抛出 `StackOverflowError`。fib(50) 就栈溢出，用户无法接受。你需要将递归转换为循环，但手工改写会引入bug。

**场景2：循环效率低下**
一个包含循环的数值计算函数运行缓慢，profiler 显示循环内部存在大量不变计算。例如：
```c
for (int i = 0; i < n; i++) {
    result[i] = input[i] + offset + scale * 0.5;  // offset和scale在循环中不变
}
```
每次迭代都重复计算 `scale * 0.5` 浪费了大量CPU周期。

**场景3：冗余计算**
代码中存在大量重复计算：
```c
int a = x + y;
int b = (x + y) * 2;
int c = (x + y) - z;  // x+y 重复计算3次
```

**场景4：死代码堆积**
遗留代码库中充满了未使用的变量、函数和不可达代码，影响编译速度和可维护性。

### 具体问题与挑战

- **尾递归识别困难**：如何准确识别真正的尾递归（函数返回时不再做其他操作）
- **循环结构分析复杂**：需要识别循环头、循环体、归纳变量
- **跨块冗余计算**：编译单元之间的表达式识别和消除
- **副作用处理**：删除代码时必须确保没有边界效应
- **优化顺序依赖**：不同优化Pass之间的相互影响

### 缺失本章能力的影响

如果缺少全局优化能力，你将面临：
- **栈溢出无法避免**：递归算法无法用于大规模数据
- **计算浪费**：循环和代码中进行大量重复计算
- **二进制体积膨胀**：死代码和冗余计算增加程序大小
- **性能瓶颈**：无法自动提升程序运行效率
- **编译器竞争力不足**：相比现代GCC/Clang缺乏关键优化

- 学会基于数据流分析的常量折叠与传播

## 人类工程师线：技术与实现

### 核心概念

#### 尾递归优化（Tail Recursion Optimization, TRO）

**定义**：当函数的最后一个操作是递归调用自身，并且返回值就是该调用的返回值（不做额外操作）时，可以将递归转换为循环。

**通俗解释**：尾递归就像俄罗斯的套娃，但你只关心最里面的那个，可以把所有的中间外壳都扔掉，直接用循环找到最后一个。

[图1：尾递归 vs 非尾递归]
```
尾递归（可优化）：
int factorial_tr(int n, int acc) {
    if (n <= 1) return acc;
    return factorial_tr(n - 1, n * acc);  // 尾调用
    //        ^^^^^^^^^^^^^^^^^^^^^^^^^^^ 返回值直接用
}

非尾递归（不可优化）：
int fibonacci(int n) {
    if (n <= 1) return n;
    return fibonacci(n - 1) + fibonacci(n - 2);  // 不是尾调用
    //        做了加法操作，不是直接返回 ^^^^^^^^
}
```

**优化转换**：
```
转换前（递归）：
    factorial(n, acc):
        if n <= 1: return acc
        return factorial(n-1, n*acc)

转换后（循环）：
    factorial(n, acc):
    loop_start:
        if n <= 1: goto loop_end
        acc = n * acc
        n = n - 1
        goto loop_start
    loop_end:
        return acc
```

**关键检测条件**：
1. 函数调用是块的最后一条指令
2. 返回语句紧跟函数调用
3. 返回值就是函数调用的返回值
4. 调用的是当前函数本身
